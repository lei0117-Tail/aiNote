## 1. 先给一个整体印象

这批辅助型 agent 不是系统主力“干活的人”，更像是给主执行链提供专项能力的角色。它们大多是：

- 子 agent
- 只做某一类问题
- 工具权限更收敛
- 更适合作为 `task`、`call_omo_agent` 或主 agent 的配套能力

你可以把它们理解成“专科顾问团”。

## 2. 最常见的几类辅助角色

### 2.1 `oracle`

定位是只读咨询型 agent。

它更像“给建议的人”，而不是“自己下场改代码的人”。从工具限制上看，它会禁止写入、编辑、继续拆任务这类动作，所以更适合：

- 给判断
- 给方案比较
- 给风险提醒
- 回答“应该怎么做”

一句话记：`oracle` 是顾问，不是施工队。

### 2.2 `librarian`

定位是资料检索型 agent。

它更偏外部文档、资料、参考信息收集。不是用来重度推进代码改动的，而是帮主 agent 把“要查的资料”先找回来。

一句话记：`librarian` 是找资料的人。

### 2.3 `explore`

定位是代码库勘探型 agent。

它和 `atlas` 不一样。`atlas` 是 orchestrator，`explore` 则更像“下去翻项目、找入口、找调用链”的侦察兵。它适合：

- 找文件
- 找实现入口
- 找相关模块
- 做局部源码摸底

一句话记：`explore` 是看代码地形图的人。

### 2.4 `multimodal-looker`

定位是多模态查看 agent。

这个 agent 不是给普通代码任务常驻使用的，而是在需要看：

- 图片
- PDF
- 视觉内容

时才有价值。它的权限也最收敛，属于非常专用的一类。

一句话记：`multimodal-looker` 是看视觉材料的人。

### 2.5 `metis`

定位是前置规划顾问。

它不是最终执行者，更像“在真正开始干之前，先帮你把思路理一下”。适合：

- 先梳理计划
- 先讨论策略
- 先做任务结构化

一句话记：`metis` 是开工前的谋士。

### 2.6 `momus`

定位是计划审阅者。

它和 `metis` 很接近，但侧重点不一样：

- `metis` 偏“帮你想计划”
- `momus` 偏“帮你挑计划毛病”

所以它更像一个 reviewer。

一句话记：`momus` 是挑计划问题的人。

### 2.7 `prometheus`

定位是更高层的战略规划 agent。

它和 `atlas` 也不一样：

- `atlas` 偏任务编排和执行落地
- `prometheus` 偏战略规划、计划产出、ultrawork 风格的方案组织

它更像“把大任务先规划成一套可执行蓝图”的人。

一句话记：`prometheus` 是战略规划师，不是现场调度员。

## 3. 这批辅助型 agent 和核心执行型 agent 的关系

可以把整个体系粗分成两层：

### 3.1 第一层：核心执行层

- `sisyphus`
- `sisyphus-junior`
- `hephaestus`
- `atlas`

这层负责真正推进主任务、拆任务、落实现、收敛交付。

### 3.2 第二层：专项辅助层

- `oracle`
- `librarian`
- `explore`
- `multimodal-looker`
- `metis`
- `momus`
- `prometheus`

这层负责给第一层补专项能力：

- 咨询
- 搜索
- 勘探
- 视觉阅读
- 前置规划
- 计划审阅
- 战略规划

所以它们不是和核心执行型 agent 平级竞争，而是给主执行链提供“外挂能力”。

## 4. 一个最简单的记法

如果只想快速记住：

- `oracle`：问意见
- `librarian`：找资料
- `explore`：看代码入口
- `multimodal-looker`：看图/PDF
- `metis`：帮你先想
- `momus`：帮你挑毛病
- `prometheus`：把大任务规划成蓝图

这样看下来，这批 agent 其实不像一堆并列的“菜单项”，而更像围绕主执行 agent 的一圈专业助手。

## 5. 最后一句总结

这套系统的 agent 设计不是“11 个都同样重要、同样用途”的平铺结构，而是明显分层的：

- 少数 agent 负责主执行和主编排
- 多数 agent 负责专项辅助

理解了这个分层，再看整个项目的 agent 架构就会清楚很多。
